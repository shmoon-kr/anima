# 2단계: Animus 연결 — 판단하는 파티

실행 계획(순서·설계·확인 방법): [`PHASE-2-PLAN.md`](PHASE-2-PLAN.md)

## 목표
1단계에서 자리만 만든 Animus(LLM 계층)에 실제 모델을 연결해, **규칙으로 풀기 어려운 판단 문제**를 LLM 이 풀게 한다.
효과는 1단계 기준선(`docs/BASELINE.md`)과 같은 지표로 비교한다.
반사·행동 선택·작업·파티 계층은 그대로 두고, LLM 은 그 위에서 **정책값·목표·거점을 바꾸는 감독**으로만 일한다 (D4, D16).

## 구조
```
 Claude 전략가 (파티)       드물게: 정기 + 긴급. 파티 블랙보드를 보고 사냥터·역할·장비 방향
 로컬 LLM (에이전트별)      자주: 상황 해석, 정책값·목표 조정, 낯선 몹·상황 판단
        │  (animus.request → 대기열 → animus.response 이벤트, 이미 있음)
 Animus 덮어쓰기 레이어     LLM 이 바꾼 값만 담는 맨 위 Sigil 레이어. 검증 후 적용, 이력·되돌리기
        │
 반사 / 행동 선택 / 작업 / 파티 / Memoria   (1단계 그대로)
```

## 만들 것 (마일스톤)
- **M0 공급자 연결**
  - 로컬: LM Studio OpenAI 호환 API. thinking 은 빈 `<think></think>` 프리필로 끈다 (mud-agents 의 `llm.py` 에서 확인한 방법).
    기본 모델은 속도 우선으로 MoE(예: Qwen3.6 35B A3B), 설정으로 교체 가능. 실제 지연시간을 측정해 기록
  - Claude: `claude -p` (API 키 없음). 시간당 호출 상한
  - 재생 공급자와 가짜 공급자는 유지 (테스트는 LLM 없이 돈다)
- **M1 Animus 덮어쓰기 레이어** ★
  - 에이전트별 `animus:<이름>`, 파티용 `animus:party` 레이어. 기존 겹쳐 쌓기(D12) 맨 위
  - LLM 이 바꿀 수 있는 것: 정책값(도주·휴식 기준, 사냥 대상, 회피, hunt_min_hp 등), 파티 거점·순환, 목표(어디로 가서 무엇을 할지),
    연습 순서, 구매 목표. **새 행동 규칙을 자동 적용하지는 않는다** (제안 파일로만 남기고 사람이 승인)
  - 모든 변경은 검증기를 통과해야 적용, 이유와 함께 `runtime.animus` 로 녹화, `anima animus history|revert` 로 되돌리기
  - 긴급 정지: `anima animus off` 면 덮어쓰기 레이어를 비우고 1단계 동작으로 돌아간다
- **M2 Claude 전략가 (파티)**
  - 입력: 블랙보드 요약, 최근 사건 압축본(킬·사망·이탈·막힘), Memoria 지식(지역 레벨표, 상점, 위험), 지난 메모
  - 호출 시점: 정기(기본 30분) + 긴급(사망, 레벨업, 10분 이상 킬 없음, 거점 도달 불가, 새 지역 진입), 최소 간격 5분
  - 출력: `animus:party` 변경 + 다음 호출에 넘길 메모(`run/party-notes.md`). mud-agents 의 strategist 경험 재사용
- **M3 로컬 LLM (에이전트별)**
  - 질문 종류를 정해서 시작: 낯선 몹 위험도, 막힘 원인, 점수가 비슷한 선택지, 자기 정책값 조정
  - 우선순위 대기열(위험 > 막힘 > 평시)과 오래된 질문 버리기는 1단계 구현 사용. 6인이 GPU 하나를 나눠 쓰는 처리량 확인
- **M4 첫 판단 과제** (아래 §5 에서 3~4개)
- **M5 비교 실행**: 고정 1시간 × 2 (Animus 켬/끔), 기준선과 같은 지표 + LLM 비용(호출 수, 지연, Claude 시간당 호출)

## 5. 첫 판단 과제 (1단계에서 넘어온 문제)
| 과제 | 지금 | 2단계에서 기대 |
|---|---|---|
| 사냥터 선택 | 5분 킬 없으면 고정 순환 | 레벨·킬 속도·시간대로 거점 선택, 이유를 메모에 남김 |
| 밤의 잠긴 성문 | 막히면 1분 뒤 되돌리기 | 해질녘 전에 거점 이동, 밤에는 성 밖 사냥터 유지 |
| 장비 | 없음 | 모은 골드로 상점에서 무기·방어구 구매 목표 설정, 교체 판단 (상점 위치·가격은 Memoria) |
| 지치는 파티원 | 리더가 기다림 | 원인 진단(예: 성직자 이동력·마나) 후 정책 조정 |
| 해독 | 없음 | 레벨 10 도달 시 remove poison 연습 목표 |
과제 하나마다 "Animus 끔" 대비 지표 변화(킬 없는 시간, 이동력 낭비, 골드→장비 전환 등)를 기록한다.

## 범위 밖
허브, 관전 웹(Speculum), MCP 서버, 빙의, 사람용 클라이언트, GMCP/MSDP, 한글화, 새 엔진,
LLM 이 쓴 새 행동 규칙의 자동 적용, 외부 에이전트와의 파티.
(작은 예외: `anima watch` 에 animus 질문·답을 보여주는 "생각" 줄 — 관전의 맛보기로 허용)

## 완료 조건
- 로컬·Claude 공급자가 연결되고, 재생 공급자로 녹화된 실행을 LLM 없이 재현할 수 있다
- LLM 이 바꾼 모든 값이 검증·녹화·되돌리기 가능하고, `animus off` 로 1단계 동작으로 즉시 돌아간다
- 반사·행동 선택은 LLM 을 기다리지 않는다 (LLM 공급자를 꺼도 파티가 계속 사냥한다)
- §5 과제 중 3개 이상에서 Animus 켬이 끔보다 지표상 낫다
- 고정 1시간 실행에서 사망·이탈이 1단계 기준선보다 늘지 않는다
- Claude 호출이 설정한 상한 안이다

## 사용자 확인 지점 ★
- Animus 가 바꿀 수 있는 값의 목록 (M1 시작 전)
- 로컬 모델 선택 (지연시간 측정 결과를 보고)
- Claude 시간당 호출 상한과 정기 호출 간격
- LLM 이 제안한 새 행동 규칙의 승인 방식

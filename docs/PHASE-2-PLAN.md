# 2단계 실행 계획

`PHASE-2.md` 가 "무엇과 왜"라면 이 문서는 "어떤 순서로, 어디를 고쳐서, 어떻게 확인하는가"다.
진행하면서 항목에 체크하고, 큰 결정은 `DECISIONS.md` 에 D26 부터 남긴다. ★ 는 사용자 확인 지점.

## 0. 출발점 (1단계에서 확인된 사실)
- 대기열·요청/답 이벤트·예산·가짜/재생 공급자는 있다 (`anima/animus/queue.py`). 실제 공급자는 없다 (`supervisor.py:96` 은 FakeProvider).
- Sigil `asks` 는 런타임에 있지만 (`agent.py` `_asks`: `when` 이 참이 되는 순간 질문, 답은 `ctx.answers`) 쓰는 패키지가 없다.
- `reload` 는 진행 중 작업을 버리고 행동 선택을 초기화한다 (`agent.py:147`). **LLM 이 값을 바꿀 때마다 이걸 부르면 안 된다** → M1 의 핫 적용 경로.
- 기준선(`BASELINE.md`)에서 가장 큰 손실: 한 시간의 약 40% 를 킬 없이 보냄, 대부분 성직자 마나 회복 대기. 사망·이탈은 이미 거의 0.
  → 2단계의 이득은 "덜 죽기"가 아니라 **"덜 기다리고, 더 맞는 곳에서 사냥하기"**에서 나와야 한다.
- 지표 도구는 `anima stats` (`anima/stats.py`). 2단계 비교는 전부 이것으로 한다.

## 1. 순서
```
 S0 준비 ─┬─ S1 덮어쓰기 레이어 (LLM 없이 완성) ─┬─ S3 Claude 전략가 ─┐
          └─ S2 공급자 연결 + 지연 측정 ★모델 ────┴─ S4 로컬 LLM ──────┴─ S5 판단 과제 ─ S6 비교 실행
```
S1 이 먼저인 이유: LLM 의 출력이 닿는 곳(검증·녹화·되돌리기·끄기)이 없으면 LLM 을 붙여도 안전하게 시험할 수 없다.
S1 과 S2 는 서로 의존하지 않아 같이 진행한다. S2 의 지연 측정 결과가 S4 설계(질문 빈도)를 정한다.

## S1. Animus 덮어쓰기 레이어 (M1) ★
**허용 목록: 결정됨** — 초안대로 승인, 단 행동 가중치는 아래처럼 좁힌다.

설계
- 레이어: `animus:party`(파티 공통) → `animus:<이름>`(에이전트) 를 기존 겹쳐 쌓기(D12) **맨 위**에 둔다. 내용은 `run/animus/overlay.json` (gitignore, 재시작해도 유지). 구현: `anima/animus/overlay.py`, 손잡이 `anima/sigil/knobs.py`
- 바꿀 수 있는 것은 **허용 목록(knob registry)** 으로 엔진에 둔다. `SIGIL-API.md` 처럼 레지스트리에서 `docs/ANIMUS-KNOBS.md` 를 생성한다
  - 정책값 `flee_pct` `rest_pct` `rest_mp_pct` `rest_mv` `rest_mv_pct` `hunt_min_hp` `targets` `shun` `danger` `skill_plan` `inv_keep`,
    파티 `rally` `circuit` `leash`, 목표 `goal`(아래 S5). 각각 타입·범위·한 번에 바꿀 수 있는 폭
  - **행동 가중치는 옵트인 (D27)**: 행동 이름은 패키지에 있으므로(D12) 패키지가 `animus_weight: [min, max]` 를 선언한 행동만 바꿀 수 있다. 기본은 못 바꾼다.
    효율 쪽만 연다: `hunt` `hunt_after_opener` `explore` `move_hunting_ground` `go_home`. `rest` `sleep` `eat` `drink` `stand_up` 과 모든 반사는 열지 않는다
    (범위 안이라도 "휴식 가중치 최저"면 지쳐도 쉬지 않는다). 정책값의 범위도 같은 원칙으로 패키지에 선언하고, `ANIMUS-KNOBS.md` 는 패키지 + 엔진 검증기에서 생성
  - 범위 밖: 새 행동/반사/작업, 식(expression), `when` 조건. LLM 이 이런 걸 원하면 `run/animus/proposals/` 에 제안 파일로만 남긴다.
    **승인 방식: 결정됨** — 제안 파일 → 사람이 패키지로 옮긴다
- 적용: `패치 = [{layer, key, value}], reason, request_id, ttl_s?`
  1. 허용 목록·범위 검사 → 2. 덮어쓰기를 얹은 프로그램 전체를 Sigil 검증기로 빌드 → 3. 통과하면 **정책·가중치만 교체**(작업·현재 행동 유지) → 실패면 거부, 이전 값 유지
  - 파티 값(`rally`, `circuit`)은 `PartyBoard` 에 바로 반영하고 저장(D20 의 `run/party.json` 과 합친다)
  - 흔들림 방지: 같은 키는 최소 유지 시간(기본 10분), 시간당 변경 수 상한. `ttl_s` 가 있으면 만료 시 아래 레이어 값으로 돌아간다
  - **소유 잠금 (D26)**: 전략가(또는 사람)가 정한 값은 파티 레이어든 그 에이전트 레이어든 TTL(없으면 최소 유지 시간) 동안 잠긴다. 그 에이전트의 로컬 LLM 패치는
    `reason: locked_by_party` 로 거부. 잠금이 없을 때만 에이전트 레이어가 자유롭게 조정한다 (전략가가 정하면 그게 이기고, 로컬 LLM 은 그 안에서 조정).
    로컬 `self_tune` 질문의 입력에 잠긴 키를 넣어 헛질문을 줄인다
  - **사망 시 자동 되돌림 (D28, 기본 켬)**: `self.died` 면 그 에이전트 레이어와 파티 레이어에서 사망 전 30분 안에 적용된 패치를 되돌린다
    (`runtime.animus {event: reverted, reason: death}`). `history` 에 "사망 뒤따름" 표시, 전략가 긴급 호출 입력에 "패치 X → N분 뒤 사망" 을 넣는다
- 녹화: `runtime.animus {event: applied|rejected|expired|reverted|off|on, layer, changes: [{key, old, new}], reason, request_id}` — PROTOCOL 2부 §7 에 추가
- 명령: `anima animus show [NAME]`, `history`, `revert <id>|--all`, `off`, `on`. `off` = 덮어쓰기 레이어를 비우고(파일은 보존) 1단계 동작, 새 패치 거부
- `anima watch` 에 "생각" 줄: 질문 요약 → 답 → 적용/거부 (PHASE-2 범위의 작은 예외)

## S4. 로컬 LLM, 에이전트별 (M3)
S2 의 지연 측정을 보고 빈도를 정한다. 6인이 GPU 하나를 나눠 쓴다.
- [ ] 첫 질문 종류 (각각 Sigil `asks` 로, 패키지에 둔다 — 엔진에는 질문 내용이 없다)
  - `mob_risk`: 지식에 없는 몹이 방에 있을 때 위험도 → 답은 `shun`/`targets` 패치 제안 (danger 우선순위)
  - `stuck`: 같은 행동이 N분 동안 진전 없음(같은 방, 같은 거부 반복) → 원인과 정책 패치 (stuck 우선순위)
  - `self_tune`: 20분마다 자기 최근 지표(대기·도주·최저 HP)로 자기 정책값 조정 (routine)
- [ ] 처리량: 6인 동시 질문 시 대기열 길이·버려진 질문 수를 `anima stats` 로 본다. 버려지는 비율이 높으면 routine 빈도를 줄인다
- [ ] 로컬 LLM 의 답도 S1 패치로만 들어간다 (에이전트 자기 레이어 `animus:<이름>` 만, 파티 값은 못 바꾼다)

## S5. 첫 판단 과제 (M4) — 3~4개
과제마다: Animus 끔 대비 지표, 필요한 엔진/패키지 작업(사람이 쓰는 규칙), LLM 이 정하는 것을 나눈다.

| 순서 | 과제 | 지표 | 사람이 먼저 만들 것 | LLM 이 정하는 것 |
|---|---|---|---|---|
| 1 | 지치는 파티원 | 대기 시간, 킬 없는 시간 | 대기 시간 지표(S0) | 원인 진단 → 성직자 `rest_mp_pct`·치료 기준·`skill_plan` 조정 |
| 2 | 사냥터 선택 | 시간당 킬·경험치, 거점별 체류 | 거점 후보 목록을 지역표에서 만들기 | `rally`·`circuit` (레벨·킬 속도·시간대) |
| 3 | 밤의 잠긴 성문 | 도달 불가 횟수, 이동력 낭비 | 해 질 녘까지 남은 시간을 상태로 노출 | 해 질 녘 전 거점 이동, 밤에는 성 밖 거점 |
| 4 | 장비 | 골드→장비 전환, 최저 HP | **상점 다녀오기 작업**(사기·입기), 장비 비교 함수 | 살 물건·예산 목표(`goal`) |
| (예비) | 해독 | 독 지속 시간 | 없음 | 레벨 10 에서 `skill_plan` 에 remove poison |

- 1 을 먼저 하는 이유: 기준선의 가장 큰 손실이고, 새 작업 없이 정책값만으로 시험할 수 있다
- **과제 1 성공 기준: 끔 대비 대기 시간·킬 없는 시간 개선, 또는 근거 있는 규칙 제안.** 가설: 원인이 정책값이 아니라
  "리더가 성직자 마나가 찰 때까지 서서 기다린다"는 구조일 수 있다. 그렇다면 LLM 이 남긴 규칙 변경 제안 파일이 정답이고,
  제안 경로의 첫 실전 시험이 된다. 제안 파일에는 지표 근거(대기 시간, 마나 곡선)를 붙인다
- 4 는 사람이 쓰는 작업(상점·장비)이 커서 마지막. 시간이 모자라면 예비 과제로 바꾼다
- `goal`(목표) 형식은 S1 허용 목록에 포함: `{kind: go_and_do, where, what, until}` 정도로 작게 시작 — 형식은 과제 4 직전에 확정 ★
